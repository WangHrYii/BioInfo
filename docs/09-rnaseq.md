# 第9章 转录组分析（RNA-seq）

> DNA 像菜谱，RNA 像厨房正在打印的订单。RNA-seq 关心：哪些菜正在做？处理前后，哪些订单变多或变少？

本章用真实公开的 `airway` 数据完成一次基因层面的差异表达和 GO 富集；再介绍剪接、融合与非编码 RNA 等分析各自回答什么问题。第一次学习先跑通 9.1–9.4，再阅读后面的扩展方向。

## 9.1 从科学问题到分析流程

假设问题是“地塞米松处理后，气道平滑肌细胞哪些基因的表达发生变化”。我们需要不同生物学来源的样本，而不只是同一个样本多测几次。

```mermaid
graph LR
    A["问题与样本设计"] --> B["FASTQ 与质控"]
    B --> C["比对或转录本定量"]
    C --> D["基因计数与样本表"]
    D --> E["质控、模型与差异检验"]
    E --> F["功能富集与图表"]
    F --> G["核对实验与独立验证"]
```

bulk RNA-seq 测到的是一群细胞的总体表达。如果肿瘤组织中免疫细胞变多，免疫基因的整体表达也会升高；不能自动解释为“每个肿瘤细胞都激活了免疫通路”。细胞组成、批次和处理效应需要结合实验背景区分。

最终交付物至少包括样本表、质控记录、计数矩阵、统计设计、完整差异结果、富集结果、图表和软件版本。只保存一份“显著基因清单”，别人无法判断你筛掉了什么。

## 9.2 基因表达定量：怎样把 reads 变成数字

### 两条常用路线

| 路线 | 输入与输出 | 合适场景 |
| --- | --- | --- |
| STAR/HISAT2 → featureCounts/HTSeq | 基因组比对 BAM + 注释 GTF → 基因计数 | 需要查看比对、兼顾剪接等分析 |
| Salmon/Kallisto → tximport/tximeta | 转录本参考 + reads → 丰度估计 → 基因层面导入 | 主要关心表达，减少完整比对开销 |

featureCounts 的思路是“落在某个基因外显子范围内的片段，就给这个基因记一笔”。实际需决定：按外显子还是基因归并、链特异性、双端按片段还是按 read 计数、多重比对和重叠基因如何处理。

对较新版本的 featureCounts，双端通常需核对 `-p` 与 `--countReadPairs` 的含义；不要只看旧教程中的一个参数。相同参考、相同注释和相同计数策略必须用于所有样本。HTSeq 也提供计数功能，但不同重叠判定策略可能产生不同结果。

Salmon 可利用选择性比对和 decoy-aware 参考减少部分误分配；Kallisto 通过兼容的转录本集合估计丰度。最终值可能不是整数，不应自行四舍五入拼成“原始 Counts”，应使用各自推荐的 tximport/tximeta 导入方法和有效长度信息。

### Counts、TPM 与标准化各负责什么

差异分析比较的是**同一个基因在不同条件之间**的变化，需要建模计数变异并考虑样本文库量。DESeq2 使用 size factor（大小因子）进行尺度调整，edgeR 常用 TMM。它们的基本假设在极端全局表达变化或组成失衡时可能受影响，必要时需要合适的 spike-in 或替代标准化策略。

TPM 是样本内部的组成量；`log2(TPM+1)` 可用于某些描述性展示，但不能直接塞进普通 DESeq2 计数模型。PCA 和热图常用 VST（方差稳定变换）或适当的对数表达，统计检验则使用原始计数及相应模型。

## 9.3 差异表达分析：变化大，还要证据够

### 先理解三个数字

- **log2FoldChange，log2FC**：处理/对照的表达倍数取以 2 为底的对数。`+1` 约是两倍，`−1` 约是一半。方向由 contrast 定义。
- **p 值**：在无差异模型及相关假设下，观察到当前或更极端统计量的概率，不是“基因没有变化的概率”。
- **padj**：多重检验校正后的 p 值。一次测几万个基因，不能每个都按未校正 0.05 判定。

Benjamini–Hochberg（BH）常用于控制假发现率 FDR。`padj < 0.05` 不表示清单中每个基因都有 95% 概率为真，而是在适用条件下控制发现集合的预期错误比例。统计显著与生物学重要也不是同一回事。

### 真实数据练习：配对来源的 airway

数据来自 [GSE52778](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE52778)，`airway` 包取四个细胞来源的未处理/地塞米松处理样本，共八个。`cell` 是来源因素，`dex` 是处理因素，因此使用 **`~ cell + dex`**，相当于先考虑每个来源自己的基线，再估计处理效应。

先安装 **R 4.4 + Bioconductor 3.20** 作为本教程环境基线。在 R/RStudio 中执行以下安装块一次；下载大小及编译要求取决于操作系统。其他 R 版本应让 Bioconductor 匹配对应发布，不要跨版本强行混装。

```r
if (!requireNamespace("BiocManager", quietly = TRUE)) {
  install.packages("BiocManager", repos = "https://cloud.r-project.org")
}
BiocManager::install(version = "3.20", ask = FALSE)
BiocManager::install(c("airway", "DESeq2", "clusterProfiler", "org.Hs.eg.db"),
                     ask = FALSE, update = FALSE)
```

项目附带完整脚本：[rnaseq_airway.R](../examples/rnaseq_airway.R ':ignore')。在项目根目录的终端运行：

```bash
Rscript examples/rnaseq_airway.R
```

或者在 RStudio 将工作目录设置为项目根目录后执行 `source("examples/rnaseq_airway.R")`。脚本从包内载入已整理计数，不下载全部原始 FASTQ；首次安装包需要联网。

核心模型代码如下，帮助你看懂脚本。已安装 `airway` 和 `DESeq2` 后可以单独在 R 中运行：

```r
library(airway)
library(DESeq2)
data("airway", package = "airway")
se <- airway
se$dex <- relevel(factor(se$dex), ref = "untrt")
se$cell <- factor(se$cell)
dds <- DESeqDataSet(se, design = ~ cell + dex)
dds <- dds[rowSums(counts(dds) >= 10) >= 4, ]
dds <- DESeq(dds)
res <- results(dds, contrast = c("dex", "trt", "untrt"), alpha = 0.05)
head(res[order(res$padj), ])
```

过滤规则“至少四个样本计数 ≥10”用于去掉几乎没有信息的基因，是本例明确选择的规则，不是所有数据的固定答案。低表达过滤不要根据“哪个基因让处理组更显著”来挑选。

| 输出文件 | 该看什么 |
| --- | --- |
| `results/rnaseq/sample_metadata.csv` | 样本身份、处理和来源是否正确 |
| `differential_expression.csv` | baseMean、log2FC、标准误、统计量、p 值和 padj |
| `normalized_counts.csv` | 调整后的表达尺度，方便描述；不重新作为原始计数输入 |
| `pca.pdf` | 样本整体关系，以及处理、来源因素 |
| `ma.pdf`、`volcano.pdf` | 表达量与效应、效应与统计证据 |
| `dds.rds`、`sessionInfo.txt` | 保存模型对象与实际环境版本 |

不同包和注释发布可能改变部分结果，不把某个“显著基因数量”当通用正确答案。`padj=NA` 可能来自独立过滤、全零或异常值处理，需结合结果列判断；不要直接把 NA 改为 0。

脚本火山图用 `padj<0.05` 且 `|log2FC|≥1` 做展示筛选，这**不等价于检验真实效应绝对值超过 1**。若科学问题要求效应阈值检验，可研究 `results(..., lfcThreshold=1, altHypothesis="greaterAbs")`。低计数基因的效应估计可能很不稳定，排序和展示可考虑 `lfcShrink`，并记录方法。

### 多组、配对、批次：设计式比按钮重要

| 实验结构 | 示例设计 | 注意点 |
| --- | --- | --- |
| 独立两组 | `~ condition` | 有独立生物学重复 |
| 每批都有两组 | `~ batch + condition` | 批次和处理不能完全重合 |
| 同一受试者前后 | `~ donor + condition` | 先考虑个体基线 |
| 两种因素共同影响 | 含主效应和交互项的设计 | 交互项要对应明确科学问题 |

多组实验可以指定某一对 contrast，也可以用似然比检验比较完整/简化模型。不要把所有两两比较混成一张没有比较名称的清单。

ComBat、`limma::removeBatchEffect` 等可在合适的变换数据上辅助展示；计数差异检验通常在设计式中纳入批次。不要把校正过的连续值当原始整数 Counts，也不要把“处理组全部在批次 A，对照全部在批次 B”当作能被软件自动解决的问题。

### DESeq2、edgeR、limma-voom 如何选

DESeq2 与 edgeR 都常使用负二项计数模型，edgeR 的准似然流程适用于许多复杂设计；limma-voom 将计数转为 logCPM 并估计均值—方差关系，再使用加权线性模型。三者都是成熟方案，优先考虑实验设计、数据性质和团队可复现的流程。不要跑三种只挑显著基因最多的一种。

## 9.4 功能富集：从基因清单读出生物学主题

如果差异基因是一堆书名，富集分析是在问“某类书是否比预期多”。它帮助概括结果，但不会把相关性自动变成机制证据。

| 方法/资源 | 问什么 | 输入 |
| --- | --- | --- |
| GO | 生物过程 BP、分子功能 MF、细胞组分 CC 有什么偏向 | 基因集合及背景 |
| KEGG | 哪些已知通路包含较多候选基因 | 物种匹配的基因 ID、背景 |
| ORA，过度代表分析 | 选中的基因里某集合是否过多 | 筛选清单 + 可被选中的背景 |
| GSEA | 某集合是否集中在完整排序的顶部或底部 | 所有可检验基因的有方向排序 |
| GSVA | 每个样本的基因集表达模式如何 | 表达矩阵 + 基因集，得分后再做适当比较 |
| MSigDB | 有哪些整理好的基因集 | 物种、版本、集合类别需记录 |

### 本例的 GO 分析怎么做

完整脚本用 `org.Hs.eg.db` 将人类 Ensembl ID 映射到 Entrez ID，再用 `clusterProfiler::enrichGO` 检查上调基因的 BP。背景取**本次得到非缺失 padj 且成功映射的受检基因**。如果把全人类基因组当背景，会把根本没测到/没机会入选的基因也加进去，改变问题。

输出 `go_bp_up.csv` 中查看 Description、GeneRatio、BgRatio、p.adjust、Count 和实际基因成员。上调和下调清单可分开分析，不能看到某通路“富集”就直接说它被激活；同一通路包含促进和抑制成分。没有合适上调基因时脚本跳过该步骤，不制造空有显著性的结果。

KEGG 分析还需要正确的物种代码及 ID，在线资源的访问、映射和授权条件依当前服务而定。GO/KEGG 条目高度重叠，应结合具体基因和表达方向归纳，而不是把几十个近义条目当几十条独立证据。

GSEA 常按有方向的 Wald statistic 等连续统计量排序；不要只交“显著基因”，不要按无方向的 p 值排序后解释上调/下调。需处理重复 ID 和缺失值，记录基因集版本、置换方案与多重检验。GSVA 得分同样不等于测到了酶活性或真实通路通量。

## 9.5 共表达网络 WGCNA：哪些基因一起变化

WGCNA 把在多个样本间共同变化的基因归成“模块”，像把总一起出现的商品分为一组。模块特征向量（module eigengene）概括模块的主要变化，再与表型关联。

典型流程：选择合适的变换表达矩阵 → 剔除明显低质量样本与低信息基因 → 检查相关结构并选网络参数 → 聚类形成模块 → 模块与表型关联 → 在独立数据检验稳定性。网络应考虑批次、离群点和样本结构。

**样本量非常重要**。WGCNA 官方建议避免少于约 15 个样本，通常至少 20 个更稳妥；这仍不是保证。airway 只有八个且含配对关系，不适合为了凑流程就建一个可靠性不足的网络。不要先只保留差异基因再把结果宣传成全转录组共表达结构。

Hub 基因指某种网络定义下连接度高的基因，不自动代表驱动基因。模块与疾病相关也可能反映细胞组成或批次，需要结合独立数据和实验。

## 9.6 可变剪接：订单总量相同，拼装方式也可能不同

同一个基因可把不同外显子组合成不同转录本。总表达没变，并不代表蛋白形式没变。

| 工具 | 常见输入 | 主要输出 |
| --- | --- | --- |
| rMATS | 有分组与重复的 RNA 比对 BAM 等 | 外显子跳跃、内含子保留等事件的差异 |
| SUPPA2 | 转录本注释与转录本丰度 | 事件的 PSI 和差异剪接统计 |

**PSI** 可以理解为“选择某个剪接方案的比例”。例如对照 PSI=0.8、处理=0.3，ΔPSI=−0.5，表示该事件的包含比例降低 50 个百分点。必须核对工具定义和组别方向。

实际做法：使用适合剪接的文库和足够读长 → 保留连接位点证据 → 检验事件并校正多重比较 → 用 sashimi plot（展示外显子覆盖和跨区间连线）查看支持 reads → 结合 RT-PCR 等验证。少量低覆盖连接不能只凭一个很大的 ΔPSI 就相信。

## 9.7 融合基因：两本书的句子被接在一起

融合转录本可能来自染色体重排，也可能是读穿转录、技术伪影或比对错误。STAR-Fusion、Arriba 等会结合跨断点 reads、支持片段和过滤规则提出候选。

真实流程通常要求合适的双端 RNA-seq、匹配的参考资源及特定 STAR 嵌合比对设置；已按普通计数目的处理过的 BAM 不一定保留所需信息。关注断点支持、唯一比对、融合伙伴、阅读框及已知伪影，并在 IGV 检查。

例如发现 BCR–ABL1 候选，意味着有值得继续核实的转录证据；要确认具体结构和意义，还需要独立实验或其他测量支持。不能把一条跨基因 read 当作已证实的融合。

## 9.8 非编码 RNA：不是所有 RNA 都拿去做蛋白

| 类型 | 常见分析 | 数据和解释重点 |
| --- | --- | --- |
| miRNA | small RNA 比对、成熟 miRNA 定量、差异表达 | 专用文库、短片段、接头处理；普通 mRNA 文库不适合直接替代 |
| lncRNA | 注释定量，或转录本组装后评估非编码候选 | 注释版本、长度、编码潜力和表达证据 |
| circRNA | CIRI2/CIRCexplorer 等识别反向剪接连接 | 建库策略、重复/同源序列和线性 RNA 干扰；poly(A) 富集不利于环状 RNA |
| ceRNA 网络 | 联合表达、miRNA 靶标和结合证据提出竞争调控候选 | 需要共表达背景、丰度和实验验证 |

ceRNA 的通俗想法是“不同 RNA 争用同一批 miRNA”。但画出 lncRNA–miRNA–mRNA 三角形并不证明竞争机制存在，相关性和数据库预测都只是候选证据。

### 读完本章，怎样检查自己的结果

先确认样本身份与模型，再看表达尺度和异常样本，之后看差异表，最后读通路与候选机制。遇到“所有基因都显著”“同组样本完全按批次分开”“只有一个样本支撑结论”，优先回到设计和数据质量。

练习：四个供体各测处理前后一次，是八个独立供体吗？不是，应考虑配对。TPM 能否直接用于 DESeq2？不能。富集到免疫通路是否证明药物直接激活了免疫机制？不能，还需排除组成变化并验证。
